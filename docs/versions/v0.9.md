# v0.9: one shared codebase and a real protocol

**Date:** 2026-09-21
**Versions:** server and client `0.9`

Cleaned up the base so new features had something solid to stand on.

## Delivered

- **Bug fixes from the base:** an empty read is treated as a closed connection
  (the client no longer spins and does reconnect), `/api/clients` returns plain
  records, `list` maps each id to its own address, commands take parameters
- **`shared/` package:** everything that was the same on both sides moved there
  (protocol, command loading, config, console, colors, network)
- **Framed protocol:** newline delimited JSON with a `type` field, so several
  messages in one write, split messages and large messages all arrive intact
- **Server to client messaging:** `send <id|all> <text>`
- Dashboard address printed at startup, including the LAN address
- `requirements.txt`, `.gitattributes`, runtime state no longer tracked in git
- [v1.0 specification](../v1.0-spec.md) written

## Roadmap items closed

1. A typed, newline framed message protocol shared by both sides
2. Server to client messaging, addressed by client id

## Left as known limitations

- One identity per checkout, several clients meant several copies of the folder
- No authentication, anyone who could reach the port was let in
- Clients not addressable by name
