The protocol did not change: a 1.2 client works with a 1.3 server.

## Delivered

### Part 1: the store

- `pyhome.db`, a SQLite database next to the server's config, through
  SQLAlchemy 2.0 ORM classes in `server/handlers/store.py`, the only module
  that knows SQL
- WAL mode, migrations numbered by `PRAGMA user_version`, each in one real
  transaction; a database newer than the code is refused
- An old `clients.json` is imported once and kept as `clients.json.imported`
- Everything the server writes lives in its data folder, one volume for a
  future container

### Part 2: state and history

- The last state of every device survives a restart
- Every change is stored with its time and source: `client`, `console` or
  `dashboard <address>`; asking for a state adds nothing
- `HISTORY_DAYS` (90) prunes old history at startup and daily
- A taken port is one readable line, checked before the database is opened

### Part 3: showing what the server remembers

- The dashboard and `/api/clients` show offline clients, gray, without
  controls, with their last state and when they were last seen
- `GET /api/clients/<id>/history` and the console's `history <id>`
- `data backup` copies the live database safely
- Console questions no longer freeze the server

### Also, done next to v1.3

- The tests moved to **pytest**, in one process, after the client's
  `handlers` package became `client_handlers`
- **GitHub Actions** runs every test on Ubuntu and Windows with Python 3.10
  and 3.13; it found a Windows only bug in `make_certs.py` on its first run
- **Architecture diagrams** in the README

## Bugs found and fixed on the way

| Bug | Found by |
| --- | --- |
| `make_certs.py` crashed for certificates on another drive than the project | CI on Windows |
| A failed migration could not be rolled back: the `sqlite3` driver runs DDL outside transactions | a test that breaks a migration on purpose |
| `data clients clear` and `data config edit name` froze the server while waiting for an answer | reading the code, then a test that counts event loop ticks |
| Clearing clients dropped the ones still connected on their next state | writing the end to end test |
| A second server started by mistake opened the first one's database | reviewing the port check |
