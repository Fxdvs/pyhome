# v1.4: easy setup, one window for the whole house

**Date:** 2026-10-31
**Versions:** server and client `1.4`
**Specification:** [docs/v1.4-spec.md](../v1.4-spec.md)
**Implementation plans:** [part 1](../superpowers/plans/2026-10-31-v1.4-part1-configs.md),
[part 2](../superpowers/plans/2026-10-31-v1.4-part2-launcher.md),
[part 3](../superpowers/plans/2026-10-31-v1.4-part3-discovery.md)

The TCP protocol did not change: a 1.3 client works with a 1.4 server.
Discovery is a separate UDP exchange that a 1.3 server simply does not answer.

**Updating from 1.3:** copy `server/data/config.json` and
`client/data/config.json` aside before `git pull`, the README says how; git
deletes them from the folder once they are no longer tracked.

## Delivered

### Part 1: configs in the launcher

- Real configs, which hold the token, are out of git; `config.example.json`
  with an empty token is tracked, and an app copies it to `config.json` on
  its first start
- `launcher/core.py`: the id from a name (`Spálňa svetlo` becomes
  `spalna-svetlo`), validating and saving client and server configs with a
  reason per field, copying `ca.crt`, generating a token, running
  `make_certs.py`

### Part 2: the desktop launcher

- `launcher.pyw` opens one window on pywebview: the server and every client
  in a sidebar with status dots and ticks, the selected app's output with its
  colors, and a command line into it
- Forms for a new or edited client and for the server's settings, token and
  certificates by button
- **Zastaviť** types `shutdown` and `y`, then terminates, then kills; closing
  with apps running asks first; ticks and selection are remembered
- The apps print plain lines without a terminal (`shared.console.interactive()`)
- The page is plain JavaScript and Tailwind 4, built with the standalone CLI
  into a committed `launcher.css` that a test keeps current
- Monochrome dark glass, color only where it means something

### Part 3: finding the server

- The server answers `{"type": "pyhome-discover"}` on UDP 50002 with its
  name, ports, TLS and the fingerprint of its `ca.crt`, never the token, at
  most 20 times a second; `DISCOVERY: false` turns it off
- **Hľadať servery** in the client form lists the servers on the local
  network; for a server on another computer the form downloads its `ca.crt`
  and keeps it only when the fingerprint matches

## Bugs found and fixed on the way

| Bug | Found by |
| --- | --- |
| `shutdown` ended the server and the client with tracebacks and tasks destroyed while pending, since v1.0 | the launcher showing the output a console window used to close on |
| On shutdown the server dropped its clients after closing the database | the end to end shutdown test |
| `wait_for_enter()` would hang an app started without a terminal | writing the runner |
| The launcher process stayed alive, invisible, after its window closed | driving the real pywebview window under Xvfb |
| Two polls at once showed console lines twice | the first Chromium run of the page |
| The sheets were too transparent to read over the console | the screenshots |
