# v1.5 Part 1: The server ready for a container Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `docker stop` ends the server as cleanly as the `shutdown` command; the server finds its data folder from `PYHOME_DATA` and the address the house uses from `PYHOME_ADDRESS`.

**Architecture:** `server/app.py` installs an asyncio `SIGTERM` handler before uvicorn starts and turns the signal into `ShutdownRequested`, the v1.4 orderly path. `shared/console.read_line()` reads the console in a daemon thread instead of the loop's pool, and both apps leave with `os._exit` after an orderly shutdown. `shared/config.init()` takes a data folder; `data_dir_from_env()` and `public_address()` read the two variables; `print_web_url()` and `make_certs.py` use them.

**Tech Stack:** Python 3.10+ standard library. pytest.

**Spec:** `docs/v1.5-spec.md`, section "Part 1", as amended in Task 3.

**Verified:** built in a scratch checkout first: 352 tests pass. A real server with a client connected and its stdin left open, as under Docker with a tty, stopped on `SIGTERM` in 0.2 s with code 0, `is shutting down (SIGTERM)`, the client let go and no WAL file. Found on the way: with the console in the loop's thread pool the server never exited (every end to end test waited 10 s for the kill); as a daemon thread it exited with code -6, Python aborting on the stdin the thread held.

## Global Constraints

- Without `PYHOME_DATA` and `PYHOME_ADDRESS` nothing changes; `--config` always wins.
- `SIGTERM` handling is skipped where asyncio has no signal handlers (Windows).
- An orderly exit closes everything before `os._exit`; no other exit uses it.
- Work happens on branch `claude/admiring-ptolemy-mfwswb`.
