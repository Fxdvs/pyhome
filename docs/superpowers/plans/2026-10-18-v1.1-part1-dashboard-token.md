# v1.1 Part 1: Dashboard behind the token Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** With a `TOKEN` set on the server, `/api/clients` answers only requests carrying it in `Authorization: Bearer <token>`, and the dashboard page asks for the token once, keeps it in `localStorage` and forgets it on **Odhlásiť** or a 401. Without a `TOKEN` the dashboard works exactly as in 1.0 and the server warns at startup.

**Architecture:** The token comparison moves out of `check_token` into `client_handler.token_matches(given)` and `token_required()`, used by the handshake and the web handler alike. `web_handler.py` gains a FastAPI dependency `require_token` on `/api/clients`, a public `/api/status`, one exception handler that turns every error into `{"error": ...}`, and `dashboard_warning()` that `app.py` prints next to the dashboard address. `/` stays public, the page holds no data. The page reads `/api/status` first, shows a login card instead of the client grid when it needs a token it does not have, and sends the token in a header on every poll. The end to end harness learns to send the token too, otherwise a server with a `TOKEN` never looks started.

**Tech Stack:** Python 3.10+, FastAPI (`Depends`, `Header`, `HTTPException`), `hmac.compare_digest`, plain JavaScript in `server/web/index.html`. Tests are plain scripts run by `py tests/run_all.py`.

**Spec:** `docs/v1.1-spec.md`, section "Part 1: Dashboard behind the token".

**Verified:** this plan's code was built and run once in a scratch checkout before it was written down: every test file passes (`test_launcher.py` needs `tkinter`, which is not installed in the cloud container), and the page was driven in Chromium through login, wrong token, reload and logout.

## Global Constraints

- Python 3.10 or newer. The client needs nothing beyond the standard library; nothing in this part touches the client.
- One `TOKEN` for clients and the browser. No second secret, no accounts.
- The token goes in the `Authorization` header, never in a URL or a query string.
- The token value is never printed or logged. Whether one is set may be shown.
- `GET /` and `GET /api/status` need no token. Everything else under `/api/` does, when the server has one.
- A server without a `TOKEN` behaves as in 1.0 for reading. (Part 2 refuses browser controls there; nothing in Part 1 controls anything.)
- `/api/status` returns only `token_required` in Part 1. Part 2 adds `controls`.
- Every API error body is `{"error": "<text>"}`.
- The protocol does not change, a 1.0 client still connects.
- Match the surrounding code: lowercase `#` comments that say why, short docstrings, no type annotations (FastAPI reads `Header(default=None)` without one). Page comments are in Slovak, like the rest of `index.html`.
- Tests need no framework: plain scripts using `tests/helpers.run_tests(globals())`, each `test_*` takes a `tmp` directory.
- Work happens on branch `claude/admiring-ptolemy-mfwswb`.
- `VERSION` stays `1.0` until v1.1 is finished.

### Task 1: Shared token check and the protected API

**Files:**
- Create: `tests/test_web_token.py`

**Interfaces:**
- Produces:
  - `client_handler.token_required()` returns `True` when the server's `TOKEN` is non-empty.
  - `client_handler.token_matches(given)` returns `True` only for a non-empty `str` equal to the server's `TOKEN`; always `False` when the server has none.
  - `web_handler.bearer_token(authorization)` returns the token from `"Bearer <token>"` (scheme case-insensitive, surrounding spaces stripped), else `None`.
  - `web_handler.require_token(authorization)` raises `HTTPException(401, "token required", headers={"WWW-Authenticate": "Bearer"})` unless the token matches; does nothing when the server has no `TOKEN`.
  - `web_handler.dashboard_warning()` returns `"No TOKEN set, anyone who can reach the dashboard sees every device"` or `None`.
  - `GET /api/status` returns `{"token_required": bool}`, no token needed.
  - Every HTTP error (including FastAPI's own 404) has the body `{"error": detail}`.

### Task 3: The page asks for the token

**Files:**
- Modify: `server/web/index.html`, `tests/test_web_token.py`

**Behaviour:**
- On load the page reads `/api/status`. If it fails (server down, or the file opened from disk) it carries on as in 1.0 and the first poll shows "Server nedostupný" or the demo data.
- Token required and none stored: the client grid becomes a login card, the overview is blanked, nothing is polled.
- **Prihlásiť** stores the token in `localStorage` under `pyhome.token` and polls at once.
- A 401 on any poll forgets the token and brings the login card back with "Nesprávny alebo zmenený token". This also covers a token changed on the server while the page was open, and a server that gained a `TOKEN` after the page loaded.
- **Odhlásiť** is shown only while logged in to a server that needs a token. It forgets the token and shows the login card.
- If `localStorage` throws (private window, blocked storage) the token lives only in the open tab.
- The server card's hint says "Chránený tokenom", or "Ovládanie je vypnuté, server nemá nastavený TOKEN".
