# v1.4 Part 1: Configs in the launcher Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Real configs, which hold the token, are out of git and an app starts from `config.example.json` when its `config.json` is missing; the launcher's logic lives in `launcher/core.py` with the config steps the form in Part 2 will call: the id from a name, validating and saving client and server configs, copying `ca.crt`, generating a token and running `make_certs.py`.

**Architecture:** `shared/config.init()` copies `data/config.example.json` to `data/config.json` when the default is used and missing; `--config` is never made from the example. `.gitignore` ignores `server/data/config.json`, `client/data/*.json` except `*.example.json`, and `launcher/state.json`. `launcher/core.py` takes everything except the window from `launcher.pyw` and adds the config functions; they return a dict of Slovak messages per field and write once, atomically, only when every field is valid. `launcher.pyw` keeps the Tkinter window until Part 2 replaces it and calls `ensure_default_configs()` first.

**Tech Stack:** Python 3.10+, standard library, `cryptography` for `make_certs.py`. pytest.

**Spec:** `docs/v1.4-spec.md`, section "Part 1: Configs in the launcher", as amended in Task 3.

**Verified:** built and run in a scratch checkout first: 270 tests pass, 1 skipped (no `tkinter`). The server started from a copy without `config.json` printed `Created .../server/data/config.json from config.example.json` and ran; `ensure_default_configs()` made the client's the same way. One test bug was found: the fixture's fake `ca.crt` without `ca.key` made `make_certs.py` refuse, which is right, so the test now uses an empty folder and a second test covers the refusal.

## Global Constraints

- The examples carry an empty `TOKEN`; a test checks it.
- `--config` with a missing file is never created from the example.
- The launcher lists client configs without `*.example.json`.
- Saving validates every field first and writes nothing when one is wrong.
- Config files are written atomically (`.tmp`, then `os.replace`), UTF-8, indent 4.
- `launcher.pyw` is loaded in tests as `launcher_window`, so it does not shadow the `launcher` package.
- Work happens on branch `claude/admiring-ptolemy-mfwswb`.

+def make_certificates(hosts=(), server_config=SERVER_CONFIG, make_certs=MAKE_CERTS, certs_dir=SERVER_CERTS_DIR):
+    """Run make_certs.py and point the server config at what it made. Returns (ok, its output).
+
+    It keeps an existing authority, so running it again renews only the server certificate.
+    """
+    command = [python_executable(), make_certs, "--dir", certs_dir]
+    for host in hosts:
+        command += ["--host", host]

+    if result.returncode != 0:
+        return False, output

+    data["TLS_CERT"] = "certs/server.crt"
+    data["TLS_KEY"] = "certs/server.key"
+    write_config(server_config, data)
+    return True, output
