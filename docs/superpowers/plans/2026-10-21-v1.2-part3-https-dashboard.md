# v1.2 Part 3: HTTPS for the dashboard Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** With `TLS_CERT` and `TLS_KEY` set, the dashboard answers only `https://`, with the same certificate as the client connections; a phone can download `ca.crt` from `/ca.crt` without a token and compare its fingerprint with the one the server prints. Without TLS the dashboard is plain HTTP as in 1.1. Then v1.2 is closed.

**Architecture:** `server/handlers/tls.py` gains `ca_file()` (the `ca.crt` next to `TLS_CERT`), `fingerprint(path)` and `uvicorn_options()`. `app.py` passes those options to `uvicorn.Config` and prints `https://` addresses plus the fingerprint. `web_handler.py` serves `GET /ca.crt` without a dependency, as `application/x-x509-ca-cert`. The page shows a `ca.crt` link on the login card and the connection type on the server card when it was loaded over HTTPS. The end to end harness learns HTTPS with full verification, since a TLS server's dashboard no longer answers plain HTTP.

**Tech Stack:** Python 3.10+, uvicorn's `ssl_certfile`/`ssl_keyfile`, `cryptography` for the fingerprint, `ssl` and `urllib` in the tests. Plain JavaScript in `server/web/index.html`.

**Spec:** `docs/v1.2-spec.md`, section "Part 3: HTTPS for the dashboard".

**Verified:** this plan's code was built and run once in a scratch checkout before it was written down. Every test file passes, `test_launcher.py` included (with a Python that has `tkinter`). The end to end test reads `/api/status` over HTTPS with host name checking at both `localhost` and `127.0.0.1`, and a context without `ca.crt` is refused. In Chromium with a real server and light: the login card's `ca.crt` link downloads `pyhome-ca.crt`, login works, the server card says `HTTPS · ca.crt`, the switch works.

## Global Constraints

- One certificate for both listeners. No new config keys: `ca.crt` is found next to `TLS_CERT`, where `make_certs.py` writes it.
- `/ca.crt` needs no token: a phone fetches it before it trusts the server, and it is public by nature. The key is never served.
- The dashboard port speaks HTTPS only with TLS set. No redirect listener.
- Without TLS nothing changes.
- Page comments in Slovak, like the rest of `index.html`. Python: lowercase `#` comments that say why, short docstrings, no type annotations.
- Work happens on branch `claude/admiring-ptolemy-mfwswb`.

"""End to end: v1.2 Part 3 "Done when", the dashboard over HTTPS with real processes."""
import os
import ssl
import sys
import urllib.error
import urllib.request

TESTS_DIR = os.path.dirname(os.path.abspath(__file__))
ROOT_DIR = os.path.dirname(TESTS_DIR)
sys.path.insert(0, TESTS_DIR)
sys.path.insert(0, os.path.join(ROOT_DIR, "server"))

from e2e import wait_for, with_system  # noqa: E402
from helpers import run_tests  # noqa: E402
import make_certs  # noqa: E402

TOKEN = "s3cret-https"


def test_dashboard_over_https(tmp):
    def scenario(system):
        make_certs.make_certs(os.path.join(system.tmp, "certs"), ["localhost", "127.0.0.1"])
        ca = os.path.join(system.tmp, "certs", "ca.crt")
        system.start_server(TOKEN=TOKEN, TLS_CERT="certs/server.crt", TLS_KEY="certs/server.key")
        system.start_client("e2e-light", "light", TOKEN=TOKEN, TLS_CA="certs/ca.crt")
        wait_for(lambda: system.client("e2e-light"), "the light on the https dashboard")

        # full verification, host name included, at both names in the certificate
        context = ssl.create_default_context(cafile=ca)
        for host in ("localhost", "127.0.0.1"):
            with urllib.request.urlopen(f"https://{host}:{system.web_port}/api/status", timeout=5, context=context) as r:
                assert r.status == 200, host

        # controls work over https as they did over http
        status, body = system.post("/api/clients/e2e-light/do", {"action": "turn_on"}, TOKEN)
        assert status == 200 and body["state"]["on"] is True, body

        # ca.crt for phones, without a token, byte for byte the file
        with urllib.request.urlopen(f"https://localhost:{system.web_port}/ca.crt", timeout=5, context=context) as r:
            with open(ca, "rb") as f:
                assert r.read() == f.read()

        # plain http to the same port is not answered
        try:
            urllib.request.urlopen(f"http://127.0.0.1:{system.web_port}/api/status", timeout=5)
        except (urllib.error.URLError, ConnectionError, OSError):
            pass
        else:
            raise AssertionError("the dashboard must not answer plain HTTP")

        # an untrusting client is refused, the certificate is not a public one
        try:
            urllib.request.urlopen(f"https://localhost:{system.web_port}/api/status", timeout=5,
                                   context=ssl.create_default_context())
        except urllib.error.URLError as e:
            assert isinstance(e.reason, ssl.SSLCertVerificationError), e
        else:
            raise AssertionError("a browser without ca.crt must not trust it")

        log = system.log("server")
        assert f"https://localhost:{system.web_port}" in log, log
        with open(ca, "rb") as f:
            ca_cert = make_certs.x509.load_pem_x509_certificate(f.read())
        assert make_certs.fingerprint(ca_cert) in log, "the fingerprint to compare on the phone"

    with_system(tmp, scenario)

        assert f"http://localhost:{system.web_port}" in system.log("server")
        assert "/ca.crt" not in system.log("server")

## Delivered

### Part 1: certificates

- `py server/make_certs.py` makes a private authority for the house
  (`ca.key`, `ca.crt`, 10 years) and a server certificate signed by it
  (`server.key`, `server.crt`, 825 days) naming `localhost`, the host name,
  its `.local` name, the LAN address and any `--host`
- A second run keeps the authority and renews only the server certificate, so
  clients and phones never need anything new; `--new-ca` starts over
- `certs/` folders are ignored by git; `cryptography` joins the server
  requirements, the client stays on the standard library
- Config paths resolve relative to the config's folder

### Part 2: TLS on the client connection

- `TLS_CERT` and `TLS_KEY` on the server, `TLS_CA` on the client
- Clients verify the chain against `ca.crt` with host name checking off, so a
  changed server address breaks nothing
- A server whose certificate cannot be used does not start
- Every mismatch ends in a readable line; a rejected certificate or a broken
  `TLS_CA` stops retrying like a refused token
- An end to end test records the wire: with TLS the token is not on it

### Part 3: HTTPS for the dashboard

- The same certificate makes the dashboard `https://` only
- `GET /ca.crt` for phones, without a token; the server prints its SHA-256
  fingerprint to compare
- The login card links to `ca.crt` over HTTPS; the server card shows whether
  the connection is encrypted
- README guide for installing `ca.crt` on Android, iPhone and Windows

### Also

- Tests: `test_make_certs.py`, `test_tls_server.py`, `test_tls_client.py`,
  `test_tls_e2e.py`, `test_https_e2e.py`; the end to end harness talks HTTPS
  with full verification when the server has TLS
- The HTTPS dashboard was checked in Chromium: login, the `ca.crt` download,
  controls

| --- | --- | --- |

| Client certificates (mutual TLS) | The token already says who may connect | not planned |
| HTTP redirecting to HTTPS | A second listener for one redirect | not planned |
| Automatic renewal | One command renews, nothing needs reinstalling | not planned |
