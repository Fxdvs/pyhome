# v1.3 Part 2: State and history Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The server stores every device's last state and, when it changes, one history row with the time and the source (`client`, `console`, `dashboard <address>`). A client that reconnects starts from its stored state. History older than `HISTORY_DAYS` (90) is pruned at startup and daily. A taken port stops the server with a readable line, before it touches the database.

**Architecture:** `store.py` gains `get_state`, `save_state` (writes `device_state` and, only on a change, `state_history`; compares parsed JSON), `get_history`, `count_history`, `history_days`, `prune_history`. In `client_handler.py` a pending request carries its `source` as a third element; `resolve_request` returns it; `remember_state` writes memory and store; `send_command` takes `source="console"`, `dashboard_do` passes `dashboard <address>`. A handshake starts `last_state` from the store. `app.py` checks both ports with `shared.network.check_port_free` before opening the database, prunes at startup, and runs `prune_daily()` in its `gather`. `server_handler` keeps the same readable message for the real bind.

**Tech Stack:** Python 3.10+, SQLAlchemy 2.0 ORM over SQLite, asyncio. pytest.

**Spec:** `docs/v1.3-spec.md`, section "Part 2: State and history", as amended in Task 4.

**Verified:** built and run once in a scratch checkout first. The whole suite passes (227 with a Python that has `tkinter`). The end to end test sees `client`, `console` and `dashboard 127.0.0.1` in that order in a real server's history, three `state` requests add nothing, the state and history survive a restart, and second servers on a taken port exit with the readable line without printing `Database`.

## Global Constraints

- Only changes go into the history. Comparison is on parsed JSON; the stored text has sorted keys.
- The source travels with the pending request; a late result is recorded as `client`.
- A refused result (`ok` not `true`) stores nothing.
- `HISTORY_DAYS`: default 90, a non-number means 90, below 0 means 0, 0 keeps no history.
- Ports are checked before the database is opened. The real bind keeps the same message.
- Tests that feed the server fake clients use the `store_db` fixture and register the fake client in the store, as a handshake would.
- The protocol does not change.
- Match the surrounding code: lowercase `#` comments that say why, short docstrings, no type annotations outside the ORM classes.
- Work happens on branch `claude/admiring-ptolemy-mfwswb`.
