# v1.3 Part 3: Showing what the server remembers Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The dashboard and its API show every client the server knows, offline ones gray with their last state and when they were last seen; a client's history is readable over the API and with `history <id>`; `data backup` copies the live database safely; questions on the console no longer stop the server.

**Architecture:** `store.py` gains `list_states()` (every state in one query), `backup()` (SQLite's backup API through the engine's raw connection) and `local_time()`. `serialize_clients()` lists connected clients from memory, then the rest from the store, each with `online` and `last_seen`. `GET /api/clients/{id}/history` reads `store.get_history`. The page treats `online === false` as offline: grayed card, no controls, "Offline, naposledy ...". Console commands `history` and `data backup` are new; `list` reads the store; `shared.console.ask()` runs `input()` off the event loop for `data clients clear` and `data config edit name`; `data clients clear` registers still connected clients again.

**Tech Stack:** Python 3.10+, SQLAlchemy 2.0 over SQLite, FastAPI, plain JavaScript. pytest, Playwright for the manual page check.

**Spec:** `docs/v1.3-spec.md`, section "Part 3: Showing what the server remembers", as amended in Task 4.

**Verified:** built and run once in a scratch checkout first: 242 tests with a Python that has `tkinter`. In Chromium with a real server, a light and a stopped thermostat: the thermostat's card is gray with "Offline, naposledy 14:33" and no controls, the light keeps its two, the overview says "1 online z 2". Two bugs were found and are covered: the old `data clients clear` and `data config edit name` froze the event loop (the new tests see 0 loop ticks against them, about 30 with the fix), and clearing removed connected clients, so their next state failed on the foreign key.

## Global Constraints

- The API's `online` field is new; a missing one (an older server, demo data) means online.
- Offline clients get no controls; `POST .../do` to one stays a 404.
- Offline states are read in one query, never one per client.
- `history` and `/history` take a full id for any known client; a prefix only for online ones, as `do`.
- Backups are named `pyhome-backup-<date>-<time>.db` and ignored by git.
- No `input()` inside a coroutine; `shared.console.ask()` instead.
- Tests that feed the server fake clients use `store_db`.
- Work happens on branch `claude/admiring-ptolemy-mfwswb`.

def answered_later(monkeypatch, answers):
    """Make input() wait until released, like a person thinking. Returns the release event."""
    release = threading.Event()
    queue = list(answers)

    def slow_input(prompt=""):
        release.wait(5)
        return queue.pop(0)

    monkeypatch.setattr(builtins, "input", slow_input)
    return release


def loop_keeps_running(command, release):
    """Run command while counting event loop ticks; release input() after a while. Returns the ticks seen."""
    ticks = []

    async def scenario():
        async def ticker():
            while True:
                ticks.append(1)
                await asyncio.sleep(0.01)

        task = asyncio.create_task(ticker())
        asyncio.get_running_loop().call_later(0.3, release.set)
        await command
        task.cancel()

    run(scenario())
    return len(ticks)
