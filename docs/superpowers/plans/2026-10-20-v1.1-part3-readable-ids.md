# v1.1 Part 3: Readable ids and id prefixes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A config copied to `kuchyna-svetlo.json` with an empty `ID` connects as `kuchyna-svetlo`; `do kuch turn_on` reaches it while it is the only online id starting with `kuch`, and is refused with every match listed once it is not; `send all` is unchanged; an id off the rule still works, with a warning. Then v1.1 is closed: version `1.1`, `docs/versions/v1.1.md`, roadmap.

**Architecture:** `shared/config.py` gains `ID_PATTERN`, `id_from_file_name(path)` and `id_warning(value)`; `load_config` stamps an empty `ID` from the file name before falling back to random hex. The client prints `id_warning` at startup, the launcher shows it as a note on the row. On the server a new `find_online_client(target)` (exact id, then an id differing only in case, then a unique case-insensitive prefix) replaces the lookups in `send_command` and `send_to_clients`; `run_and_print` resolves the target first so its lines carry the full id. The web API keeps exact ids: `dashboard_do` looks the id up exactly before `send_command` sees it.

**Tech Stack:** Python 3.10+ standard library (`re`), asyncio, tkinter for the launcher. Tests are plain scripts run by `py tests/run_all.py`.

**Spec:** `docs/v1.1-spec.md`, section "Part 3: Readable ids and id prefixes".

**Verified:** this plan's code was built and run once in a scratch checkout before it was written down. Every test file passes, `test_launcher.py` included (run with a Python that has `tkinter`). The end to end test drives the spec's "Done when" with real processes.

## Global Constraints

- The id stays the only thing that addresses a client. `NAME` is never matched.
- An id off the rule is a warning, never a refusal, and nothing is renamed automatically: the id is the key in `clients.json`.
- "it cannot be typed in commands" is said only for an id holding whitespace, the one case where it is true.
- `config.json` and file names that are not a usable id (or are `all`) keep getting `uuid4().hex[:8]`.
- Ambiguous is an error, never a guess. Only online clients count.
- `all` stays reserved for `send`.
- The web API takes full ids only.
- The default `client/data/config.json` keeps `"ID": "1"`.
- The protocol does not change.
- Match the surrounding code: lowercase `#` comments that say why, short docstrings, no type annotations.
- Tests need no framework: plain scripts using `tests/helpers.run_tests(globals())`.
- Work happens on branch `claude/admiring-ptolemy-mfwswb`.

  a missing or wrong one gets `401 {"error": "token required"}`
- `/` and the new `/api/status` stay public, the page needs them to ask
- The page asks for the token once, keeps it in `localStorage`, and forgets it
  on **Odhlásiť** or any 401
- A server without a `TOKEN` keeps the open dashboard of 1.0 and warns at
  startup

### Part 2: device controls on the dashboard

- `POST /api/clients/<id>/do`, only on a server with a `TOKEN` (403 otherwise)
- Light: switch and brightness slider. Thermostat: switch and **−** / **+**
  by 0.5 °C. Other devices: each action as a button
- The grid updates card by card, so a running request or a dragged slider is
  never redrawn by the poll; errors show in the card for 4 s
- Every browser action prints a line on the server console with its address
- `send_command` refuses an action the device does not list before sending it,
  for the console's `do` too

### Part 3: readable ids and id prefixes

- An empty `ID` is taken from the config file's name (`kuchyna-svetlo.json`
  becomes `kuchyna-svetlo`), `config.json` still gets a random one
- The id convention `room-device` is written down; an id off the rule gets a
  warning in the client and the launcher, never a refusal
- `do`, `state` and `send` take the start of an id when exactly one online
  client matches it, in any case; an ambiguous prefix is refused with every
  match listed; the success line prints the full id
